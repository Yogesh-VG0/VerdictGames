# Validation of the November 12 audits

Reviewed November 14, 2026 (Asia/Kolkata). Review only: no application, database, GitHub, or Vercel settings were changed. This file records the review.

## Conclusion

The audits identify several real, fixable problems. Their strongest findings concern personalized caching, database privacy, avatar ownership, reliability, and navigation. Their suggested implementation details are not all safe to apply verbatim. Some observations describe the older `d2101ef` deployment; current production is `94011f269dad78f45dc8449198da6d88adec16d7` and is READY.

Use `FRONTEND_DIRECTION.md` as the more considered design proposal. It correctly retracts deleting Explore, removing most discovery rails, making every navigation bar identical, and changing the brand to score green. Its remaining visual choices are proposals, not proven conversion or SEO improvements.

## Verification performed

- Read all three documents and checked the current source for their cited mechanisms.
- Queried live Supabase policies, effective column privileges, migration history, duplicate Steam IDs, Hades' stored cons, and the November calendar snapshot. No private note contents, secret values, or user identities were retrieved for this review.
- Used the Vercel plugin to verify production deployment, region metadata, and active firewall configuration.
- Queried GitHub branch protection, rulesets, and vulnerability-alert status. Reviewed both quality and maintenance workflows.
- Opened Hades at 768px and inspected the rendered navigation geometry and screenshot.
- Checked current primary documentation for PostgreSQL privileges, Motion reduced-motion behavior, Vercel regions/headers/billing, Supabase password protection, and WCAG non-text contrast.

Further browser/API probes reached Vercel's 429 Security Checkpoint. Those probes did not establish current authenticated cache behavior or complete phone/dialog journeys. Protection was left enabled. No two-user exploit test, destructive account-deletion test, new load test, Search Console inspection, or complete keyboard/screen-reader pass was performed. A successful deployment is not proof of complete security or sitemap coverage.

## Corrections required before implementation

1. **Column privileges:** PostgreSQL privileges are additive. Revoking selected columns does nothing while the role retains table-wide SELECT. Revoke the broad grant and explicitly grant safe columns, or redesign the public projection and underlying permissions. RLS OR policies also do not hide columns. Update trusted own-role lookups and joins at the same time. [PostgreSQL REVOKE documentation](https://www.postgresql.org/docs/current/sql-revoke.html).
2. **Region versus cause:** Tokyo colocation is sensible for database-heavy requests and a single selected region fits Hobby. It cannot repair an unhealthy database, expensive SQL, or a provider outage by itself. Compare latency/error rates after moving rather than promising the 300-second failures will disappear. [Vercel region guidance](https://vercel.com/docs/functions/configuring-functions/region).
3. **CPU versus memory:** Idle database wait does not consume billed Active CPU. Provisioned memory continues during in-flight requests, with instance concurrency affecting totals. Reducing hangs improves availability and memory use but does not by itself explain the original Active CPU exhaustion. [Vercel Fluid pricing](https://vercel.com/docs/functions/usage-and-pricing).
4. **Password protection price:** Leaked-password checking is Pro and above, not a free toggle for this project. [Supabase password security](https://supabase.com/docs/guides/auth/password-security).
5. **Reduced motion:** MotionConfig disables transform/layout animations when reduced motion is active; opacity and other animation types persist. Explicitly stop gradient/background loops and unwanted opacity/height effects where necessary. [MotionConfig documentation](https://motion.dev/docs/react-motion-config).
6. **Contrast numbers:** 28% white on black is below 3:1, as the direction document correctly notes. However, 42% is a proposed safety margin, not the WCAG rule. Contrast must be measured against adjacent colors and applies to visual information needed to identify controls/states; not every card or chip needs a border. [WCAG 1.4.11](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html).
7. **Client IP:** Vercel documents that it overwrites forwarded-for to prevent spoofing in its normal setup. The audit's generic last-hop recommendation is not an established vulnerability or an automatically correct fix on this project. [Vercel request headers](https://vercel.com/docs/headers/request-headers).
8. **Backups and redundancy:** The audit's pattern matrix is too generous when it labels some vendor failover and thread-safety concerns already handled. Multi-region failover is plan-dependent; overlapping async work still shares process state. A previous Vercel deployment restores application code, not deleted database data. Verify available backups and export/restore steps separately.

## Recommended order and expected improvement

1. **Privacy and integrity:** VG-002, VG-005, VG-007, then the narrowly scoped grants in VG-006. Expected result: user-specific data and avatar writes stay within the intended identity boundary.
2. **Reliability and free-tier efficiency:** complete VG-001, fail closed for VG-011, recover the RAWG circuit, and make deferred maintenance/freshness visible. Preserve public catalogue caching and the bounded GitHub worker.
3. **Release safety and recovery:** CI build, protected checks, dependency alerts, reconciled migrations, and documented database restore steps. These reduce regression risk; they do not make every deployment bug-free.
4. **Product truth:** repair stored Early Access cons and calendar campaigns, clarify/implement deletion, and review duplicate provider mappings without losing URLs or users' references.
5. **Targeted UX:** tablet header, stable phone destinations, search density, loading names, actual contrast failures, reduced motion, then a contextual Compare action.
6. **Optional visual polish:** adopt Signal incrementally if desired: keep artwork, discovery rails, numeric scores, the existing routes, and a restrained brand accent. Neutral primary buttons, static headings, exact radii/timings, and provider-strip removal remain design choices to validate.

Most of this work is achievable with the existing stack and no paid service. No rewrite, Redis, queue, Kubernetes, new animation library, or scoring redesign is justified by these audits. Neither the audits nor this review can guarantee permanent free-tier availability, perfect SEO rankings, or absence of all vulnerabilities.
