# Reviewed data repairs and non-destructive mapping handling

`duplicate-steam-mappings.json` records the current 54 groups / 108 public game rows, established slugs, provider IDs, and aggregate reference counts. It contains no private note, review body, or user identity. Examples include old/new Counter-Strike names, base/GOTY Borderlands, original/enhanced Quake II, and Stronghold/Stronghold HD. These are not all safely interchangeable editions. Some legacy rows have list references and Counter-Strike 2 has review/library references. No record, relationship, slug, redirect, or canonical URL was changed.

The scheduler now requests each valid Steam app's player count once and fans the result out to all referencing rows. This saves 54 requests for the presently reviewed duplicate set on a full pass; the unit test proves grouping, not an executed full production pass. It does not fix uncertain edition mappings. A merge/unique constraint remains Deferred pending an edition-by-edition ownership/source review, all foreign-key references, public links, conflict resolution, and redirects. The snapshot is evidence, not permission to merge.

`legacy-generated-cons.json` is the read-only preview of affected public rows. Both ingest paths stop creating the unsupported sentence, and the game mapper suppresses exactly that sentence from old rows. We do not infer current Early Access from a historical tag or invent replacement criticism. The proposed SQL removes only that exact generated sentence, preserving every other con and all game records. It defaults to ROLLBACK; do not execute/commit until a concrete data repair is approved and the preview/backup refreshed. Restore the saved per-row cons arrays if an approved repair must be undone.

Calendar advertisements are filtered at live mapping, durable-snapshot read, merge, and final database presentation. The new framework namespace avoids reusing old merged calendar values; old durable snapshots are read through the filter without forcing an upstream request just to rewrite history. No snapshot/game is deleted. Invalidate `/calendar`, `/api/calendar`, and `/api/gx/calendar` during an approved deployment to remove already-cached CDN payloads. Test November's actual snapshot after rollout.
